# fuelog 세부 개발 일정 — 2026-10-29 ~ 2026-11-15

작성일: 2026-10-29 (KST)  
기준: [fuelog 기획서](fuelog-product-plan-2026-11-15.md)  
인력: 2명 / **각자 주중 2시간, 주말 10시간** 기준  
목표: Pleos 차량 앱과 Android 휴대폰 앱을 공통 백엔드로 연결한 시연용 MVP 및 제출 자료 완성

## 1. 일정 기준과 현재 진척

사용자가 알려준 ‘2명, 주중 2시간, 주말 10시간 이상’을 **1인당 작업시간**으로 해석했다. 주말 추가 시간은 계획에 선반영하지 않는다. 두 사람의 합산 시간이라는 의미라면 아래 범위를 줄여 다시 산정해야 한다.

기획서의 10/26~10/28 작업을 완료한 것으로 간주하지 않고 현재 저장소를 기준으로 재배치했다. 이 문서가 앞으로 실행할 일정이며, 원 기획서의 10절은 최초 계획으로 남긴다.

| 확인 항목 | 10/29 현재 상태 | 일정에 반영한 내용 |
| --- | --- | --- |
| HTTP 통신 기반 | `ApiClient`, `ApiModule`, URL 설정, INTERNET 권한이 있음 | 재사용. 통신 모듈을 처음부터 다시 만들지 않음 |
| API 테스트 | `ApiClientTest`가 있음 | 코드 존재만 확인. 이번 일정 작성에서 테스트를 실행하지 않았으므로 재검증 필요 |
| 차량 화면 | main Manifest에 실행 Activity 없음 | 실행 화면·상태 처리부터 구현 |
| 차량 SDK | 현재 Gradle에 Pleos 의존성 없음 | 실제 SDK/권한/데이터 조회 검증을 첫 작업으로 배치 |
| 휴대폰 앱 | `settings.gradle`에 `:app`만 있음 | `:mobile` 모듈 신규 구성 |
| 백엔드 | 저장소에서 구현·배포 완료 근거를 찾지 못함 | 기획서의 Supabase안을 기본 일정으로 사용. 외부 서버가 이미 있으면 첫날 확인 후 재사용 |
| 제품 흐름 | QR·운행 세션·개인 차계부 구현은 확인되지 않음 | 신규 작업으로 계획 |

코드 기준 HEAD는 `edf4019`이며 미커밋 변경을 포함해 정적으로 확인했다. 앱 코드, 기존 기획서, 환경 설정은 수정하지 않았다. 이번 문서는 새 정책 감사나 실차 검증 결과가 아니라, 기획서에 정리된 제약과 검증 항목을 작업 일정으로 옮긴 것이다.

## 2. 역할 분담과 필수 범위

실명이 정해지지 않아 A/B로 표기한다. 두 사람의 강점에 따라 통째로 역할을 바꿀 수 있다.

| 담당 | 소유 범위 | 주요 산출물 |
| --- | --- | --- |
| A — 차량 앱·수집/전송 | 차량 `app`, 차량 SDK adapter, 차량 QR/세션 화면, 암호화 outbox, 공통 HTTP 기반, 차량 업로드 함수 | 차량 APK, 차량 이벤트 계약, `ingestVehicleEvents` 구현·검증 |
| B — 휴대폰·계정/DB | `mobile`, 로그인·확인함·차계부, DB migrations/RLS, 그룹/초대, QR 승인·운행 확정·공유 함수 | 휴대폰 APK, 서버 DB/권한, `approvePairing`, `confirmTripUser`, `confirmFuelEvent` 등 |
| 함께 — 매일 짧게 | API 계약, 오류 응답, 통합 시연, 교차 계정 접근 검증 | 연결 동작 영상, 재현 가능한 검증 기록 |

공통 모듈·루트 Gradle 변경은 A가 관리하고 B가 필요한 항목을 먼저 전달한다. DB 스키마 변경은 B가 관리한다. A의 업로드 함수는 B가 확정한 테이블·세션 검증 규칙을 사용한다. 함수 이름은 기획상의 제안이며 실제 파일·경로는 첫 주말 전에 확정한다.

### 11/15까지 반드시 완성할 기능

- [ ] 차량 앱과 휴대폰 앱을 각각 설치·실행할 수 있다.
- [ ] 휴대폰에서 개인 계정 로그인·로그아웃이 된다.
- [ ] 정차 중 일회용 QR로 차량 앱 설치와 그룹/계정을 연결한다.
- [ ] 운행마다 사용자를 확인하고 시작·종료를 구분한다.
- [ ] 연료·거리 중 지원되는 데이터를 읽고, 주유 후보 또는 운행 기록을 생성한다.
- [ ] 서버를 거쳐 휴대폰에서 기록을 조회하고 금액을 확정한다.
- [ ] 다른 계정·그룹·차량 설치 주체가 개인 원장을 읽거나 수정할 수 없다.
- [ ] 재전송해도 중복 기록이 생기지 않고, 계정 전환 후 기록 귀속이 유지된다.
- [ ] 미지원·오프라인·세션 만료 상태를 구분해서 표시한다.
- [ ] 두 APK, 설치 안내, 시연 영상, 실제 구현과 일치하는 기획 문안을 준비한다.

**2순위:** 명시적 비용 공유와 N분의 1 계산. 11/7에 구현하되 핵심 흐름이 밀리면 후속으로 이동한다.  
**3순위:** FusedLocation 단일 위치 보조. 11/8에 전체 2인시 이내 실험 후 결정한다.  
**이번 일정 제외:** BLE 자동 인식, FCM, 실시간 비용 미터기, 시동 자동 시작/종료 보장, 연속 이동 경로, 실제 송금, EV·내비·음성 기능.

기획서의 BLE 반나절 실험도 이번에는 제외한다. 제한된 주중 시간과 남은 SDK 작업을 고려해 QR 기반 사용자 확인을 완성하는 데 집중한다.

2. A 계정으로 이번 운행을 확인한다.
3. 지원 데이터 또는 명시된 테스트 신호로 거리/주유 후보를 생성한다.

5. B 계정으로 전환해 A 개인 내역이 보이지 않는 것을 보여준다.
6. 구현했다면 공유한 비용만 B에게 보이는 것을 보여준다.
7. 오프라인 재전송 후 중복이 없는 결과를 짧게 보여준다.

기능 미구현을 정적인 화면으로 대체한 구간은 동작 시연과 구분한다. 시연 환경·데이터 출처·검증하지 못한 실차 조건을 영상 설명 또는 기획서에 남긴다.
