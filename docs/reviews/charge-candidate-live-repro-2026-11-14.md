# 충전 후보 실제 재현

Pleos Connect v2.1.0 에뮬레이터와 127.0.0.1:8088 콘솔에서 실제 저장된 사용자 연결로 실행했다. UID·사용자명·인증정보는 기록하지 않았다.

| 단계 | 앱 관측 결과 |
| --- | --- |
| P / Switch OFF / Energy 30kWh / Capacity 60kWh / SOC 50% | 사용자 확인됨, 화면 사용 가능, 후보 0 |
| Port OPEN / Switch ON / 8초 | 충전 전용 구간 시작, 시작 에너지 30kWh, 구간 생성 API 성공 |
| Energy 31kWh / 8초 | 에너지 31kWh 수신, 후보 1건 생성, 충전 후보 동기화 API 성공 |
| Energy 32kWh / 8초 | 같은 후보 1건 유지, 에너지 32kWh 수신, 동기화 API 성공 |
| Switch OFF / 8초 | 구간 종료, 후보 1건 유지, 저장 오류 없음 |

콘솔 입력값은 종료 후 초기 상태(Energy 32kWh / Capacity 60kWh / SOC 50% / Switch OFF / Port CLOSED)로 복원했으며 비교로 확인했다. 확인한 범위에서는 후보 생성·업로드 실패가 재현되지 않았다.

후속 서버 GET·화면 재조회 검증은 실패했으나 앱 복원 버그의 근거로 사용할 수 없다. Gradle UTP 로그에서 `uninstall_after_test: true`와 대상 앱 삭제를 확인했다. 첫 테스트 종료 후 앱이 삭제되어 후속 실행의 로컬 연결 및 기록이 없었다. 서버 업로드 성공 로그는 삭제 전 확보한 결과다. 앱은 다시 설치했으며 사용자 QR 재연결이 필요하다. 로컬 기록 복원과 서버 GET 조회 완료를 주장하지 않는다.

`LiveChargeScenarioAndroidTest`는 `runLiveChargeScenario=true` 명시 시에만 동작하는 수동 프로브다. 실제 데이터를 유지해야 하는 기기에서 `connectedDebugAndroidTest`로 실행하지 않는다. 타깃 APK와 테스트 APK를 업데이트 설치한 뒤 현재 Android 사용자로 `am instrument`를 직접 실행한다. 콘솔 입력은 finally에서 복원한다. 실제 서버에 테스트 충전 기록이 생성될 수 있다.

## 연결 유지 후 재검증 및 전기차 화면 반영

이후 검증은 APK를 `install -r`로 업데이트하고 현재 사용자(10)에서 `am instrument`를 직접 실행했다. 앱 삭제는 하지 않았다. 실제 사용자 연결이 유지된 상태에서 다음을 확인했다.

- 초기 콘솔 호출 중 HTTP 503, `{error:emulator_inactive}` 응답을 확인했다. 콘솔 HTML의 `/browser/session` 1초 heartbeat와 같은 활성 세션 유지 처리를 수동 프로브에 추가한 뒤 재현했다. 자신의 테스트 세션만 종료한다.
- ON에서 30kWh 기준을 잡고 31→32kWh를 수신해 후보 1건 생성 및 업로드 성공.
- OFF에서 충전 관측 구간 종료. 관측 충전량 2kWh, 서버 revision 저장 확인.
- 별도 프로세스의 읽기 전용 검증으로 실제 `GET charge-candidates/{id}` 재조회 성공: HTTP 200, CANDIDATE, estimatedKwh=2.0.
- `운행 > 충전 기록 > 충전 관측 요약`에서 기록 복원·상태 확인 버튼을 검증했고 주유 탭이 제외됨을 확인했다. 충전 전용 상세에서 운행 소모 전력량/전비/운행 금액/N빵은 제외한다.
- CONFIRMED 응답의 correctedKwh/correctedAmount/correctedPlace 렌더링은 별도 메모리 fixture(1.8kWh·9,500원·테스트 장소)로 확인했다. 실제 서버 후보는 CANDIDATE이며 실제 결제 완료로 변경하지 않았다.

충전 이력은 완료된 충전 관측 구간과 운행 중 충전 후보가 있는 구간을 운행 화면에 계속 표시한다. 전기차 판별은 확인된 최신 기록의 evDetected를 사용한다. 관측 충전량과 사용자 확인된 실제 내용은 구분한다. 이번 테스트의 충전 후보·기록은 서버/로컬에 남아 있다.

## 탭 동작 정정

사용자 정정에 따라 전기차에서 탭을 제거하던 처리를 취소했다. 현재 최종 구성은 홈·운행·충전·정비 네 개이며 주유 탭 자리에서 이름과 내용을 충전으로 전환한다. 충전 탭 안에서 충전 목록·관측 상세·후보 서버 상태 조회가 동작하고 목록 복귀/뒤로 가기도 같은 탭을 유지한다. 운행 화면의 충전 이력 진입도 유지한다.

검증 시 다른 작업의 런처 아이콘 PNG/WebP 중복으로 원본 작업 트리의 리소스 병합이 실패했다. 원본 아이콘 파일은 수정하지 않고 임시 복사본에서 중복을 정리해 빌드·설치했다. 원본 앱 연결과 데이터는 업데이트 설치로 보존했다.

## 충전 그래프·완속 추정금액 검증

충전량/금액 탭과 기존 일·월·년 막대그래프를 충전 화면에도 적용했다. `ChargeHistoryTest` 2개(보정 충전량과 원 반올림, 중복·기각 제외, 미확인 금액 제외) 및 Android 단위 테스트가 통과했다. 백엔드 ChargingTests 10개도 통과했으며 충전 시작 시점에 유효한 완속 요금만 선택하고 동기화 시 스냅샷을 유지하는 것을 검증했다.

실제 시나리오는 최초 실행 도중 외부 force-stop으로 중단됐고, 이어 8088 forward와 8080 reverse가 사라진 상태를 확인했다. 포트 연결 복구 후 13:58~13:59 재실행은 통과했다. 사용자 연결 유지, P/0km/h, OFF→ON, Energy 30→31→32kWh, OFF 순서로 후보 한 건 생성·증가·종료를 확인했다. 서버 GET HTTP 200, CANDIDATE, estimatedKwh=2.0, REFERENCE_ESTIMATE, scenarios=1을 확인했다.

14:03 저장 기록 재조회 테스트도 통과했다. 서버 SLOW 단가 295원/kWh, 앱 추정금액 590원(2kWh×295원)을 대조했으며 충전 탭의 실제 렌더링도 확인했다. 금액/충전량 탭 전환, 일 그래프 24개·년 그래프 12개 막대, 충전 상세 진입을 검증했다. 실제 결제나 모바일 확인 상태 변경은 수행하지 않았다. 콘솔 에너지 77.400002kWh/용량 77.400002kWh/SOC 100%/포트 닫힘으로 복원됐으며 충전 스위치는 OFF로 종료했다. 테스트 충전 기록은 서버·로컬에 남아 있다.

백엔드 소스 변경의 운영 배포는 수행하지 않았다. 현재 연결 서버의 완속 단가 응답과 앱 금액 표시를 확인한 것이며 모든 충전소·요금 조합의 실환경 검증은 아니다.

## 운행·충전 표시 분리

후속 요청에 따라 운행 목록의 충전 이력·충전 관측 진입을 제거했다. 운행 상세는 소모 전력량·전비·운행 비용을 유지하고 충전 스위치·충전 후보 내용은 충전 탭에서만 표시한다. 충전 탭에서 운행 탭으로 보내던 링크를 제거하고 현재 진행 중인 충전 상세 진입은 충전 탭으로 옮겼다. 저장 기록과 서버 동기화는 변경하지 않았다.
