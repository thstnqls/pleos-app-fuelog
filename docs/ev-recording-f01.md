# EV 기록 및 F01 차량 앱 연결 (2026-11-08)

EV 후보 저장·주변 충전소 참고요금 계산의 최신 계약은 [EV 충전 연동](ev-charging-integration.md)을 따른다. 아래 F01은 내연기관 주유소용 계약이다.

## 전기차 C04

현재 사용자를 확인하고 화면이 보이는 동안 3초 주기로 관측한다. 운행 거리는 기존 D→P 구간을 사용하며 충전량은 Pleos getEvChargeSwitchState의 ON 구간에서 관측한 배터리 증가분으로 계산한다. ON 최초 유효 배터리를 기준으로 잡고 OFF 전환 때 마지막 증가분까지 반영한다. OFF 상태의 배터리 증가는 충전 후보를 만들지 않는다. 정차 중 ON이 관측되면 별도 앱 관측 구간을 기존 recording-intervals 계약으로 시작하고 OFF의 유효 배터리 수신 후 닫는다. 이 충전 전용 관측 구간은 운행 거리 계산에서 제외한다. 백그라운드 수집은 추가하지 않았다.

배터리 읽기 전후로 Pleos 충전 스위치를 확인하며 두 값이 다르거나 null/오류이면 그 샘플은 연결하지 않는다. 배터리는 AAOS `EV_BATTERY_LEVEL`을 우선 사용하고 Wh 미수신이면 Pleos SOC와 AAOS 완충 용량으로 환산한다. 용량은 `EV_CURRENT_BATTERY_CAPACITY` 우선, 미지원 시 `INFO_EV_BATTERY_CAPACITY`를 사용한다. 서로 다른 계산 출처/용량, 앱 이탈, 시간 초과, 권한/연결 실패 사이의 값을 연결하지 않는다. N/알 수 없는 기어를 거친 구간도 보수적으로 연결하지 않는다.

- Wh → kWh: Wh / 1000
- SOC → kWh: SOC / 100 × 완충 Wh / 1000
- 증가: P kWh − 기준 kWh. 양수일 때만 `CANDIDATE`로 저장한다.
- 소모량: D/R 기준 kWh − P kWh. 0 이하/누락/증가 포함 구간은 전비 계산 불가.
- 전비: 유효 거리 / 유효 소모 kWh
- 비용 함수: 유효 소모 kWh × 검증된 `chargeUnitPriceWonPerKwh`. 현재 단가 수집 API가 없어 실기록에서는 금액 미표시.

배터리 증가는 회생제동·온도·SOC 보정으로도 발생할 수 있다. 충전/결제 완료로 확정하지 않는다. 이는 배터리에 저장된 에너지의 변화이며 충전기 계량 전력량이나 충전 손실 포함 결제량을 보장하지 않는다.

새 EV 기록은 `noBackupFilesDir/ev-recordings.bin`에 AES-GCM으로 저장한다. 기존 운행 SharedPreferences에는 새 배터리 필드를 추가하지 않는다. 복구 시 후보는 보존하고 이전 실시간 기준값은 재사용하지 않는다. 기존 사용자 변경 시 종료·모바일 전달 흐름을 유지한다.

### 서버 확장 필요

기존 `PUT recording-intervals/{id}`에 아래 필드를 보낸다. 충전 후보는 별도 `POST /charge-candidates/sync`로 저장하며, EV 요약은 선택적인 `ev` 객체로 업로드한다. fuelog-backend에 EV 후보 API와 요금표를 구현했다. 모바일 화면 연결과 실차 전체 흐름은 미검증이다.

```json
{
  "evDetected": true,
  "evEndpointsValid": true,
  "evMissing": false,
  "consumedKwh": 4.0,
  "chargedDuringInterval": false,
  "chargeCandidates": [
    {"id": "UUID", "status": "CANDIDATE", "startAt": 1000, "endAt": 2000,
     "basis": "AAOS_WH", "estimatedKwh": 12.0}
  ]
}
```

운행 ID가 부모 키이며 후보 시간은 epoch milliseconds이다. 후보를 가진 구간은 `chargedDuringInterval=true`이다. 가격 없는 후보를 0원 결제로 저장하지 않는다. 원격 성공 응답은 기존 업로드 계약을 따른다.

## F01 (내연기관 주유용)

오피넷의 원/L를 전기차 원/kWh에 적용하지 않는다. PDF 12~13쪽의 `aroundAll.do`, `detailById.do`를 확인했다. KATEC 좌표, 유종 코드, 상세 조회 가격 기준 일시를 요구하며 전기차 충전 요금 API가 아니다.

C07의 차량 위치 보조 동의는 기본 꺼짐이다. 기존 FUSED_LOCATION 권한이 없으면 래퍼가 실패 처리하고 권한 팝업을 자동 실행하지 않는다. 인증된 `connection/settings` 응답에서 다음 메타데이터가 필요하다.

```json
{"pleosCoordinateSystemVerified": false, "fuelType": "B027"}
```

`pleosCoordinateSystemVerified=true`는 서버/운영자가 대상 SDK·기기 좌표계를 검증한 경우에만 제공해야 한다. 차량 앱에서 임의로 활성화하는 설정은 없다. 미확인 또는 유종 불명이면 검색하지 않는다. 서버 설정 새로 확인 전에는 보수적으로 검색 비활성 상태다.

최초 % 증가 후보 생성 시 차량의 새 위치 업데이트를 한 번 요청한다. 10초 제한·측정 시각·범위·이동 여부를 확인한다. 위치는 메모리에만 보유하며 후보 종료/앱 이탈/사용자 전환/동의 철회/최종 성공·실패에 폐기하고, 최대 24시간 후 폐기한다. 원래 주유 후보는 유지한다. 증가가 6초간 새 최고값 없이 유지되면 안정으로 간주하고 후보를 먼저 동기화한다. 서버 수신 확인 후 위치 증거를 전송한다.

`POST fuel-candidates/{id}/station-search` 인증된 HTTPS 본문:

```json
{
  "candidateId": "UUID", "latitude": 37.0, "longitude": 127.0,
  "measuredAt": "ISO-8601", "receivedAt": "ISO-8601",
  "source": "PLEOS_CURRENT_UPDATE", "fuelType": "B027",
  "locationOperationId": "station-search:UUID"
}
```

응답은 사용자 요청의 계약대로 `candidateId`, 증가한 `revision`, `searchStatus`, `locationMeasuredAt`, `stations[]`를 사용한다. C05는 상위 3개 후보와 후보별 유종·거리·유효 가격·가격 기준 시각을 표시한다. `VALID`라도 현재 시점 기준 24시간 이상 오래된 가격, 0/누락 가격, 불명 유종, 미래 일시는 사용하지 않는다. 선택된 주유소 ID와 유효 가격 근거가 서버에서 돌아온 경우만 추정 L × 게시 원/L를 표시한다. 선택 전 통합 금액을 만들지 않는다. 자동 검색은 최초 포함 최대 3회 시도하며 늦은 결과의 후보 ID·revision·현재 사용자·상태를 확인한다.

### 서버에 남은 필수 작업

- 설치/후보 소유권·유종·좌표·신선도 재검증, 검증된 좌표계 → KATEC 변환
- `aroundAll.do` 1km → 결과 없으면 3km 한 번, 거리순 상위 3곳
- `detailById.do` 같은 유종의 PRICE/TRADE_DT/TRADE_TM, 가격 기준 시각·조회 시각 보존
- 후보/위치 작업 ID 멱등성, 캐시·429 대응·유한 재시도
- 원시 좌표 목적 제한, 성공/실패 후 24시간 내 삭제 및 동의 철회/후보 삭제 처리
- 모바일 주유소 선택·확인·기각과 revision 일치

현재 차량 앱이 종료되면 위치 작업을 재개하지 않으며 위치 없는 후보를 보존한다. 서버에 이미 전송된 좌표의 삭제는 서버·모바일 동의 철회 계약의 구현이 필요하다. 이 저장소의 로컬 동의 철회만으로 서버 삭제 완료를 주장할 수 없다.

## C04 수집·전력비 연결 수정 (2026-11-09)

운행 기록기도 Pleos Vehicle.initialize()를 호출한다. 차량 기본정보의 독립 거리 표시와 이번 운행 거리 수집은 별도이므로 기록 시작 후 유효한 누적거리 샘플 두 건이 필요하다. 연결·설정에서 AAOS CAR_ENERGY 권한을 요청할 수 있으며, 운행 요약에는 권한 부족·충전 스위치 대기·비충전 배터리 샘플 대기·수신 누락을 구분해 표시한다. 배터리 권한이 있어도 기기 property 지원이 필요하다.

2026-11-11부터 운행 전력비는 아래의 완속 3개 사업자 평균 최초 저장 방식으로 변경했다. 기록 시작 시 최근 충전 후보 단가를 가져오는 경로와 C04의 충전소별·출력 구간별 금액 목록은 제거했다. 충전 증가 후보의 감지·모바일 확인 흐름은 유지한다.

현재 수집은 앱 화면이 활성화된 동안의 수동 기록이다. 백그라운드 연속 수집과 기존 누락 데이터 복원은 제공하지 않는다.

## 운행 전송 오류와 현재 위치 참고요금 (2026-11-09)

- SDK Float 누적거리 차이는 소수점 3자리(km, 1m)로 반올림해 로컬 합계와 전송을 맞춘다. 1샘플에서 1000km 초과 점프는 누락 사유로 전송한다. 서버가 400 INVALID_DISTANCE로 거부한 이전 샘플만 동일 batchId/sequence로 보정한다. 성공·타임아웃 요청의 본문은 바꾸지 않는다.
- 첫 sequence=1의 baseline_required는 시작 기준값이므로 서버의 기록 누락 집계에서 제외한다. 이후 baseline_required와 실제 실패는 누락으로 유지한다. 409 RECORDING_QUALITY_MISMATCH로 거부된 이전 요약은 missing=true로 재시도하고 소모량·전비·비용을 과장하지 않는다.
- 기존 `charging-reference`는 호환 API로 남아 있지만 C04에서는 호출하지 않는다. 운행 비용은 아래의 `ev-cost` API로 최초 한 번 저장한다.
- 서버에 좌표계 검증 설정이 없거나 최근 카탈로그·유효 요금표·비교 사업자가 부족하면 사유만 표시한다. 이 경우 비용을 만들지 않는다.

## 조회 위치·시설 주소 표시

2026-11-11부터 C04에는 충전소별 이름·주소·거리 목록 대신 총 추정 전력비 한 건을 표시한다. 비용 조회의 위경도·측정 시각은 해당 세션에서만 확인할 수 있다. C05 연료차 화면에는 ‘현재 위치로 주유소 이름·주소 조회’가 있으며, 유종 선택 후 차량 위치를 1회 받아 서버 오피넷 조회를 수행한다. 이 현재 위치 조회는 기존 주유 감지 위치를 대체하지 않는다. 전기차 배터리 기록이 확인된 경우 C05 진입도 C04 충전 정보로 연결한다.

위도·경도와 차량 측정 시각은 해당 요청 ID와 현재 사용자에 묶어 화면에 표시한다. SDK가 보고한 위경도를 표시할 뿐, 표시 여부가 WGS84·KATEC 검증을 의미하지 않는다. 원시 좌표는 메모리에만 두고 화면 이탈 또는 사용자 해제 시 지운다. 이후 과거 기록에 현재 좌표를 끼워 넣지 않는다. 좌표 수신 실패와 주소 누락은 각각 명시한다.

충전소 주소는 서버 V16 마이그레이션과 카탈로그 재수집 이후 제공된다. 이전 가격 스냅샷의 주소가 없으면 ‘주소 정보 없음’을 표시한다. 오피넷은 서버 OPINET_KEY와 검증된 OPINET_KATEC_PROJ4 및 PLEOS_COORDINATE_SYSTEM 설정이 필요하다. 설정이 없으면 위경도는 표시하되 검색은 진행하지 않고 설정 사유를 표시한다.

## 충전 스위치 기준 변경 (2026-11-10)

getEvChargeSwitchState는 충전 스위치 상태다. ON 자체를 실제 충전·결제 완료로 확정하지 않고, ON 구간에서 실제 증가량이 있을 때만 차계부 후보를 만든다. OFF에서 마지막 값 수신 실패 시 OFF로 추측해서 완료하지 않는다. 이전 값을 이어 붙이지 않으며 누락으로 보존한다. 스위치 읽기에는 Pleos CAR_ENERGY 권한을 사용하고 제어 API는 호출하지 않는다.

Wh 또는 SOC/완충 용량으로 환산한 kWh의 측정 기준이 바뀌면 기존 기준값을 끊는다. 같은 ON 구간의 후보 ID는 유지하며 증가량이 내려간 샘플로 누적 추정량을 줄이지 않는다. 새 ON 구간은 새 기준과 후보를 사용한다. 후보 생성 이후 6초 안정성·현재 사용자·위치 증거 검사는 기존과 같다. 이전 실행의 ON 기준값을 복원해 새 값을 합산하지 않는다.

비충전 구간의 전력 소모량은 연속된 배터리 샘플의 순감소량이다. 충전이 섞인 구간·누락 구간의 전비는 계산에서 제외한다. 운행이 P에서 끝날 때 마지막 배터리 샘플을 반영한 후 종료한다. 충전 전용 구간의 마지막 관측 시각·후보는 기존 서버 계약으로 전송하며 거리 유효 여부는 false이다.

단위 테스트는 OFF 중 증가 제외, ON→OFF 마지막 증가량, 두 충전 구간 ID 분리, null/소스 변경/복구 시 기준 단절, SOC 환산을 확인한다. 에뮬레이터 통합 테스트는 정차 충전 구간 시작·종료와 기존 전송 큐·운행 요약 회귀를 확인한다. 실제 차량의 ON→OFF 충전 전환은 미검증이다.

## C04 완속 평균 비용 최초 저장 (2026-11-11)

P단 종료 시 마지막 거리·배터리 샘플을 반영해 로컬 운행과 전송 큐를 먼저 저장한다. 위치 권한이 이미 있으면 새 Pleos 위치 업데이트 1건을 요청하고, 같은 운행의 서버 업로드·요약 검증 후 `POST /recording-intervals/{tripId}/ev-cost`로 비용을 붙인다. 위치·요금 응답을 기다리며 운행 저장을 보류하지 않는다. 위치 권한을 자동 요청하지 않는다.

계산은 유효한 소모 kWh × 주변 서로 다른 3개 사업자의 완속(<30kW) 일반 회원 참고단가 산술평균이다. 반경 1km에서 부족하면 3km로 한 번 넓히며, 사업자당 가장 가까운 한 곳만 사용한다. 평균은 소수 6자리, 최종 합계는 원 단위 HALF_UP으로 반올림한다. C04에는 시설 3곳이나 출력별 시나리오를 노출하지 않는다.

위치 권한이 없거나 위치·요금 자료가 부족해도 거리와 유효한 소모량은 저장된다. 운행 동기화 후 정차 중 ‘금액 확인하기’를 누르면 권한을 요청할 수 있다. 나중에 확인할 때는 **확인 시점의 새 차량 위치**로 주변 시설을 찾으며, **운행 종료 시각 당시 서버에 보관된 유효 요금 버전**을 사용한다. `tariffDate`는 운행 종료일(KST), `calculatedAt`은 실제 최초 금액 저장 시각이다. 운행 날짜를 확인 날짜로 바꾸지 않는다.

서버 V18의 `trip_ev_costs`에 운행당 한 건을 저장한다. 동일 요청·동시 요청·단가 갱신에도 최초 금액과 시각을 유지하며, 금액을 저장한 운행의 소모 kWh 변경도 거부한다. 기존 서버에 이미 금액이 있는 EV 운행은 원래 금액을 보존한다. 비용이 나중에 붙어도 기존 모바일 확인함 항목에 반영하며 운행·확인함을 추가 생성하지 않는다.

`GET .../ev-cost`는 위치 권한 없이 저장된 금액만 읽는다. 응답이 유실됐어도 요약 재진입 시 서버 값을 복구하며, 저장된 금액에는 다시 계산하는 버튼이 없다. 계산 요청용 좌표는 최대 30초 동안 메모리에 두고, 화면 표시용 좌표는 앱 이탈 시 지운다. 서버 DB·로그·오프라인 전송 큐에는 원시 좌표를 저장하지 않는다.

서버 좌표계 검증, 최근 24시간 이내 카탈로그, 운행 시각의 유효 완속 요금과 서로 다른 사업자 3곳이 모두 필요하다. 자료가 없으면 현재 요금이나 전국 평균으로 대신 계산하지 않는다. 최초 보관 요금 이전 날짜 및 요금 유효기간 공백의 기록은 비용을 계산할 수 없다.
