# fuelog 차량·모바일 화면 기획 및 기능 요구사항

작성일: 2026-10-31 · 버전: 1.0 · 대상 마감: 2026-11-15

## 1. 제품 방향과 이번 문서의 범위

**차량에서는 기록과 상태 확인을 간단하게, 모바일에서는 수정·정산·정비·공유를 충분하게 제공한다.** 자동으로 얻은 값은 추정 기록으로 보관하고, 사용자가 확인한 거래와 구분한다.

사용자가 제시한 차량 기능 4개와 모바일 기능 5개를 모두 화면에 연결했다. 이 문서는 목표 설계이며, 현재 구현 완료 목록이나 Pleos 심사 통과 판정이 아니다. 기존 제품 기획서·일정표·앱 소스는 수정하지 않았다.

기준 자료: `docs/fuelog-product-plan-2026-11-15.md`, `docs/fuelog-development-schedule-2026-10-29.md`, `docs/vehicle-diagnostics.md`, 현재 Manifest와 진단 코드, 아래 공식 문서. 문서 안의 외부 작업 지시는 사용자 요청으로 취급하지 않았다.

## 2. 기능을 확정하기 전에 바로잡을 계산·동작

### 2.1 주유 감지와 비용

‘5% 증가’는 **연료 잔량 5퍼센트포인트(pp) 증가**로 정의한다. 예: 30% → 35%는 5pp. 이는 초기 탐지 기준이며, 차량 센서 검증 후 조정할 제품 설정이다.

```text
연료량(mL)을 읽을 수 있을 때:
  추정 주유량(L) = (주유 후 mL − 주유 전 mL) / 1,000

연료 비율(%)만 읽을 수 있을 때:
  추정 주유량(L) = (주유 후 % − 주유 전 %) / 100 × 탱크 용량(L)

추정 주유 금액(원) = 추정 주유량(L) × 조회 단가(원/L)
```

50L 탱크에서 30% → 70%, 단가 1,700원/L이면 **추정 20L·34,000원**이다. 화면 예시 값이며 실제 주유소·가격 데이터가 아니다.

- `Fuel`은 SDK 클래스다. 캡처하는 값은 `getFuelPercent()` 결과 또는 AAOS `FUEL_LEVEL`이다.
- 주유는 시동을 끈 동안에도 발생한다. 이전 정지 직전의 유효 샘플을 저장하고 다음 실행의 안정된 샘플과 비교한다. 시동 ON 값 하나만으로는 감지할 수 없다.
- 연료 흔들림·경사·센서 지연·반올림 때문에 증가를 즉시 주유 확정으로 처리하지 않는다. 여러 유효 샘플에서 증가가 유지되면 **주유 후보**를 만든다.
- 첫 실행, 이전 샘플 없음, 중간 주행 누락, 센서/단위/차량 변경이면 비교 보류. 탱크 용량이 없으면 % 증가까지만 표시한다.
- 5pp 미만 소량 주유를 놓칠 수 있으므로 모바일 수동 등록을 항상 제공한다.
- 위치·오피넷은 주유소 후보와 게시 가격을 제공한다. 실제 방문 지점·카드 할인·실제 결제 금액을 확정하지 않는다.
- 감지 위치가 이미 주유소에서 멀어진 경우 직전 정차 위치가 유효할 때만 후보 탐색에 사용한다. 오래된 위치를 현재 주유소로 표시하지 않는다.

### 2.2 운행 비용과 연비

```text
주행거리(km) = 종료 누적거리(km) − 시작 누적거리(km)

추정 소모 연료(L) = (시작 FUEL_LEVEL(mL) − 종료 FUEL_LEVEL(mL)) / 1,000
또는
추정 소모 연료(L) = (시작 연료% − 종료 연료%) / 100 × 탱크 용량(L)

추정 연비(km/L) = 주행거리(km) / 추정 소모 연료(L)
추정 운행 연료비(원) = 추정 소모 연료(L) × 적용 단가(원/L)
```

위 단순식은 **측정 구간 안에 주유가 없고, 양 끝 값이 유효하며, 센서 변화량이 신뢰 가능한 경우**에 적용한다. 주유가 끼면 주유 전후 구간으로 분리한다. 분리할 샘플이 없으면 비용 계산을 보류한다. 소모량 0 이하·누적거리 감소·센서 분해능보다 작은 차이는 ‘계산 불가’로 표시하며 0원/무한 연비로 표시하지 않는다.

단가 정책: 사용자가 정산에 지정한 단가 → 동일 차량·유종의 최근 확인된 주유 단가 → 날짜와 출처를 표시한 오피넷 참고 단가 순으로 제안한다. 최신 단가로 과거 운행을 몰래 다시 계산하지 않는다. 운행별 적용 단가·출처·계산 버전을 고정 저장한다. 원 단위 반올림은 최종 합계에서 수행한다.

**주유비는 구매 지출이고 운행비는 소비 비용이다.** 같은 연료를 월 지출에 두 번 더하지 않는다. ‘지출’에는 주유·정비 거래, ‘운행 분석’에는 소비 추정 비용을 표시한다. 주행 가능거리(DTE)는 연료량 대신 쓰지 않는다.

### 2.3 사용자 확인과 개인정보

- BLE는 GATT, SPP는 Bluetooth Classic/RFCOMM 계열이다. ‘BLE SPP’를 하나의 API 이름으로 사용하지 않는다.[B1][B2]
- 목표 연결안은 BLE GATT 기반 인증 정보 전달이다. 실제 Pleos 단말의 역할·권한·광고/스캔·백그라운드 지원 검증이 선행되어야 한다. SPP는 별도 대안이며 지원을 가정하지 않는다.
- 기존 차량 오디오 Bluetooth 연결은 앱 간 데이터 채널이나 운전자 증명이 아니다. MAC 주소·평문 사용자 ID를 계정 전환의 인증 근거로 사용하지 않는다.
- QR 등록 → 모바일 로그인 → 차량 멤버십 확인 → 짧은 수명의 일회용 연결 증명 → 차량의 연결 챌린지 확인 → 이번 운행 사용자 확정 순으로 설계한다. 휴대폰의 장기 로그인 토큰은 차량으로 보내지 않는다.
- 등록 휴대폰이 하나라도 실제 운전자라는 보장은 없다. 초기 버전은 정차 상태에서 ‘이번 운행에 사용’ 확인을 받는다. 여러 폰이면 임의 선점 금지. 자동 확정은 추가 제품 검토 사항이다.
- 사용자 미확정 기록은 제한된 차량 보관함에 둔다. 다른 멤버에게 노출하지 않고, 이후 인증된 요청과 차량 확인을 결합해 귀속시킨다. 누구나 차량의 미귀속 기록을 가져가는 API를 만들지 않는다.
- 개인 운행은 기본 비공개. 공유는 대상·항목·기간을 확인한 후 실행한다. 차량 관리자도 개인 운행 전체를 자동 열람하지 못한다.
- 차량 공용 누적거리·정비 이력으로 차량 사용 사실이 추정될 수 있다. ‘완벽한 익명성/프라이버시’라는 문구는 쓰지 않는다.

## 3. 화면 구조와 디자인 원칙

```text
Pleos
  C01 차량 연결 → C03 이번 운행 사용자 확인 → C02 홈
  C02 홈 → C04 운행 요약 / C05 주유 감지 / C06 정비 요약 / C07 연결·설정
  모든 화면 → C00 주행 제한 상태 → 제한 해제 후 안전한 화면으로 복귀

모바일 하단 메뉴: 홈 / 운행 / 차계부 / 관리
  M01 로그인 → M02 차량 등록·참여 → M03 홈
  홈 → M04 휴대폰 연결·운행 사용자 / M13 알림함
  운행 → M05 운행 목록 → M06 운행 상세 → M08 여행 정산 → M09 정산 상세
  차계부 → M10 주유·정비 내역 → M07 주유 확인 / M11 정비 기록 / M12 정비 예정
  관리 → M14 차량·멤버·기기·공유·계정 설정
```

브랜드 시안: fuelog의 강조색은 차분한 녹색, 숫자는 큰 크기, 보조 문구는 짧게. 이는 공식 색상 토큰 값이라고 주장하는 것이 아닌 제품 제안이다. 실제 구현에서는 Pleos 자산의 의미별 색상 토큰에 매핑한다. 웹 시안의 px는 차량 글자 mm·터치 영역 검증을 대체하지 않는다. 글꼴은 Asta Sans 또는 동일 수준으로 읽기 쉬운 시스템 서체를 검토한다.[D5]

## 4. Pleos 페이지별 상세 요구사항

차량의 C01–C07은 정차 전용이다. ‘정차’는 속도 0만을 뜻하지 않으며 플랫폼이 조작을 허용하는 상태를 따른다. 신호 대기에서 임의로 잠금을 해제하지 않는다. 화면 저장·전환이 서버 요청을 포함하면 권한 확인과 중복 방지 키를 사용한다.

### C00. 주행 제한 및 복귀 상태 — 페이지가 아닌 공통 처리

- **목적/진입:** `CarUxRestrictions` 제한 진입 또는 상태 조회 불가. 플랫폼이 앱을 차단할 수 있다.
- **표시:** 앱 UI 표시가 허용된 경우만 ‘정차 후 확인할 수 있어요’. 플랫폼 차단 UI를 자체 화면으로 대체하지 않는다. 수집이 확인되지 않았다면 ‘기록 중’이라고 표시하지 않는다.
- **FR-C00-1:** 최초 현재값과 변경 리스너를 반영하고, 설정/키보드/콘텐츠 제한값을 중앙 제어한다.[S1]
- **FR-C00-2:** QR를 즉시 숨기고 등록 nonce를 만료시킨다. 사용자 전환은 보류하고 현재 운행 소유자를 바꾸지 않는다. 늦게 도착한 응답도 제한 검사를 다시 거친다.
- **FR-C00-3:** 복귀 시 현재 제한과 로그인 상태를 재확인한다. 민감한 이전 상세 대신 C02로 복귀하고, 확인이 필요한 작업만 다시 제안한다.
- **완료 기준:** C01 QR, C03 사용자 선택 중 제한 진입·Activity 재생성·서비스 연결 실패에서 내용 누출/자동 승인 없음. DO 미선언의 플랫폼 차단은 정상 동작으로 인정한다.

### C01. 최초 차량 연결

**구성:** 상단 fuelog → ‘휴대폰으로 차량을 연결하세요’ → QR와 남은 시간 → 연결 대기/완료. QR 옆에는 짧은 단계 안내만 둔다.

- **진입/이동:** 설치 후 미등록 상태 또는 C07 연결 초기화 → 모바일 M02 → 성공 시 C03.
- **표시 데이터:** 차량 연결 요청 식별자, 만료 시간, 네트워크 상태. QR에 이름·VIN·장기 인증 토큰을 넣지 않는다.
- **FR-C01-1:** QR는 일회용 등록 요청만 담고 유효기간은 초기 제안 2분. 인증 비밀을 URL query/path에 노출하지 않는 별도 앱 페이로드 방식으로 설계한다.[S2]
- **FR-C01-2:** 휴대폰에서 로그인·차량 확인을 마치면 서버가 설치 기기와 차량을 묶는다. 기존 등록 차량은 새 차를 중복 생성하지 않는다.
- **FR-C01-3:** 재발급하면 이전 요청은 무효화. 등록 중 화면 회전이나 요청 재전송으로 차량이 두 개 생기지 않는다.
- **예외:** 오프라인은 QR 대신 연결 필요 안내, 만료는 ‘코드 다시 받기’, 이미 연결된 기기는 C07로 안내. 등록 실패로 과거 기록 삭제 금지.
- **완료 기준:** 만료/재사용 QR 거부, 다른 차량 요청과 교차 등록 불가, 주행 제한 시 등록 승인 보류 또는 재시작.

### C02. 차량 홈

**넓은 창:** 상단 차량 별칭·현재 사용자 / 왼쪽 이번 운행 거리와 추정 비용 / 오른쪽 주유 확인·정비 예정 / 하단 운행 요약·연결 상태.
**좁은 창:** 사용자 → 이번 운행 → 확인할 항목 순으로 쌓고 보조 항목은 상세로 보낸다.

- **진입/이동:** 연결 완료·정차 복귀. 사용자 영역 C03, 운행 C04, 주유 C05, 정비 C06, 연결 C07.
- **표시 데이터:** 기록 상태, 마지막 샘플 시각, 이번 거리, 비용 상태, 동기화 상태, 필요한 알림 건수. 타인의 최근 주행/지출은 표시하지 않는다.
- **FR-C02-1:** 사용자 미확정이면 개인 금액 대신 ‘이번 운행 사용자를 확인하세요’. 이름을 선택만 해 타인 계정으로 들어갈 수 없도록 모바일 증명을 요구한다.
- **FR-C02-2:** 자동 수집 조건이 충족된 경우에만 ‘기록 중’. 그 외 ‘기록 준비/연결 필요/일부 누락’ 상태를 명시한다.
- **FR-C02-3:** 자동 시작이 미지원인 MVP는 정차 상태의 ‘기록 시작/종료’를 제공하고 앱 기록 구간임을 명시한다. 실제 시동 구간과 동일하다고 표시하지 않는다.
- **예외:** 연료 미지원이어도 거리 기록은 제공. 서버 오프라인이어도 유효한 로컬 상태와 저장 시각 표시. 오래된 값은 ‘최근 수신’으로 표현.
- **완료 기준:** 연료 오류가 전체 홈 오류로 번지지 않고, 사용자 전환 때 이전 사용자의 카드/캐시가 즉시 사라진다.

### C03. 이번 운행 사용자 확인

**구성:** ‘이번 운행은 누가 기록하나요?’ → 인증된 휴대폰 후보 → ‘이번 운행에 사용’ → ‘휴대폰으로 연결’ 보조 액션.

- **진입/이동:** C01 완료·C02 사용자 영역·새 연결 후보 수신 → 확정 후 C02.
- **표시 데이터:** 인증된 연결 후보의 최소 표시명, 해당 차량 멤버 여부, 확인 만료. 주변 미등록 기기명/전체 멤버 개인정보를 나열하지 않는다.
- **FR-C03-1:** 후보가 하나여도 초기 버전은 확인한다. 모바일 M04에서 동일 차량/운행에 대한 동의를 받아 서버가 검증한다.
- **FR-C03-2:** 둘 이상이면 선택 필요 상태. 연결 시각·신호 세기만으로 운전자 결정 금지.
- **FR-C03-3:** 이미 시작한 운행은 연결 변경만으로 소유자를 변경하지 않는다. 정차 후 구간 종료·새 구간 시작에 동의하면 이후 기록부터 적용한다.
- **예외:** 인증 만료/멤버십 해제/오프라인 검증 불가이면 전환 보류. 기존 기록 소유권은 유지하고 미확정 신규 구간은 별도 보관.
- **완료 기준:** 다른 사람 ID·재전송 증명·만료 토큰 거부. 주행 중 새 폰 연결로 프로필/운행 소유자 변경 없음.

### C04. 운행 요약

**구성:** ‘이번 운행’ → 거리 → 추정 소모량·연비·연료비 → 기록 품질 → ‘모바일에서 상세 확인’.

- **진입/이동:** C02 운행 카드. 종료 시 화면을 강제로 띄우지 않고 다음 정차 앱 진입에서 제안. 모바일 M06로 이어짐.
- **표시 데이터:** 시작·종료 시각, 거리, 비용 상태, 적용 단가 출처 요약, 누락 여부. 상세 경로 지도/공유 대상 편집 없음.
- **FR-C04-1:** 양 끝 샘플과 단가가 유효한 항목만 표시. 일부 계산 불가여도 유효한 거리 제공.
- **FR-C04-2:** 저장 상태를 로컬 저장/서버 동기화 완료로 구분한다. 이미 저장된 운행을 화면 재진입 때 새로 만들지 않는다.
- **FR-C04-3:** 모바일 전달은 운행 ID 기반 앱 내 확인함에 기록. 이 버튼이 휴대폰 앱 자동 실행을 보장하지는 않는다.
- **예외:** 강제 종료 후 복구된 운행은 종료 시각 추정·누락 상태 표시. 중간 주유와 사용자 변경 구간을 합쳐 잘못된 연비를 만들지 않는다.
- **완료 기준:** 60km·4L·1,700원/L 입력에서 15km/L·6,800원, 0L이면 계산 불가, 통신 재시도해도 운행 한 건.

### C05. 주유 감지 요약

**구성:** ‘주유 기록 확인이 필요해요’ → 주유소 후보 또는 ‘주유소 미확인’ → 추정 L과 조건부 추정 원 → ‘모바일에서 확인’. F01의 여러 주유소 가격은 후보별로만 표시한다.

- **진입/이동:** C02 확인할 항목 → 모바일 M07. 차량에서는 장소·금액 수정이나 결제 행동을 제공하지 않는다.
- **표시 데이터:** 감지 시간/구간, 추정 주유량, 후보 주유소명, 단가 기준 시각, 사용자 확인 전 상태.
- **FR-C05-1:** 증가 감지를 주유 완료/결제 완료로 표현하지 않는다. 후보가 여러 개면 특정 상호를 확정 표시하지 않는다.
- **FR-C05-2:** 계정 귀속이 불명확하면 이름·금액을 숨기고 사용자 확인을 먼저 요청한다. 공용 화면에 이전 사용자의 주유 내역을 띄우지 않는다.
- **FR-C05-3:** 모바일 확인 이후 상태만 갱신한다. 반복 감지로 동일 후보를 여러 건 만들지 않는다.
- **FR-C05-4:** 차량에서 주유 증가를 감지했을 때의 위치로 주유소 게시가격 후보를 보강하는 동작은 신규 기능 F01을 따른다. 이 위치는 모바일 GPS로 대체하지 않는다.
- **예외:** 위치 권한 없음/오피넷 실패 시 양만 보존하고 수동 보정으로 연결. 용량 미확인 시 ‘잔량 증가 감지’, L·원은 미표시.
- **완료 기준:** 후보/확인/기각 상태가 모바일과 일치하고, 주행 중 확인 팝업·즉시 수정 알림을 강제로 띄우지 않는다.

### C06. 정비 요약

**구성:** ‘차량 관리’ → 마지막 유효 누적거리·갱신 시각 → 다음 정비 항목 최대 2개 → ‘모바일에서 기록’.

- **진입/이동:** C02 정비 카드 → 모바일 M11/M12.
- **표시 데이터:** 공동 관리 대상으로 선택된 항목의 마지막 정비일/거리, 사용자 지정 또는 제조사 기준의 다음 예정일/거리. 개인 메모·영수증은 제외.
- **FR-C06-1:** 남은 거리와 남은 기간 중 먼저 도달할 조건을 안내한다. 최신 누적거리가 없으면 ‘최신 거리 확인 필요’.
- **FR-C06-2:** 정비소 방문 추정만으로 ‘교체 완료’를 만들지 않는다. 정비 기록은 모바일 확인 후 생성한다.
- **예외:** 항목/주기가 없으면 모바일 설정 안내. 지연됐다고 고장 확정이나 위험도 점수를 표시하지 않는다.
- **완료 기준:** 정비 등록 후 다음 예정이 갱신되고, 과거 정비 기록 수정 시 관련 예정이 재계산된다.

### C07. 연결·설정

**구성:** 휴대폰 연결 상태 / 기록·동기화 상태 / 데이터 제공 상태 / 연결 해제.

- **진입/이동:** C02 연결 아이콘 → 재등록 C01 또는 모바일 M14.
- **표시 데이터:** 연료·거리·위치 각 기능의 지원/권한/일시 실패, 마지막 동기화, 연결한 기기 별칭. 일반 화면에는 SDK 오류 코드 대신 원인과 해결 행동.
- **FR-C07-1:** 자동 사용자 추천 활성화는 등록·동의·기능 검증이 완료된 경우만 노출. 휴대폰 M04 설정과 연동한다.
- **FR-C07-2:** ‘이번 사용자 연결 해제’와 ‘차량 등록 초기화’를 분리한다. 후자는 관리자 재인증과 미전송 기록 처리 안내를 요구한다.
- **FR-C07-3:** 개인 세션 종료 시 표시·캐시·접근 토큰을 정리한다. 다른 사용자의 미전송 기록을 현재 사용자로 업로드하지 않는다.
- **예외:** 서버 해제 대기 상태에서는 로컬 표시를 먼저 잠그고, 원격 연결도 해제된 것처럼 표시하지 않는다.
- **완료 기준:** 연결 해제 후 이전 사용자의 상세를 뒤로가기/재시작으로 볼 수 없고, 재시도 상태가 유지된다.

## 5. 모바일 페이지별 상세 요구사항

모바일 앱은 차량 제한을 우회하는 즉시 조작 경로로 사용하지 않는다. 운행 중임을 알고 있는 경우 운전자에게 입력·보정·정산을 즉시 요구하지 않고 나중에 확인할 작업으로 저장한다. 알림이 꺼져도 앱 내 확인함은 동작해야 한다.

### M01. 로그인·최초 동의

- **화면:** fuelog 소개 한 문장 / 이메일 로그인·가입 / 계정 복구 / 필수 약관 / 선택 기능 설명.
- **진입→다음:** 비로그인 또는 세션 만료 → M02(차량 없음) / M03(차량 있음). 푸시 딥링크는 로그인 후 권한을 재검사해 목적 화면으로 이동.
- **FR-M01-1:** Supabase Auth 세션 기반 로그인. 초기 버전은 이메일 방식 한 가지로 제한하고 소셜 로그인은 후속 확장한다.
- **FR-M01-2:** 위치·근처 기기·알림 권한은 해당 기능 시작 시 목적을 설명하고 요청. 선택 권한 거부로 로그인 자체를 막지 않는다.
- **FR-M01-3:** 서버 오류와 입력 오류를 구분하고 중복 제출 방지. 비밀번호·토큰을 로그에 남기지 않는다.
- **예외/완료:** 로그인 만료 후 다른 계정으로 진입하면 이전 계정 캐시 숨김. 복구 요청은 계정 존재 여부를 불필요하게 노출하지 않는 안내로 처리.

### M02. 차량 등록·초대 참여

- **화면:** ‘차량 등록’ QR 스캔 / ‘초대받은 차량 참여’ 코드 입력 → 차량 별칭·유종·탱크 용량 확인 → 등록 완료.
- **입력:** 차량 별칭 필수, 유종 필수, 탱크 용량은 읽기 가능 시 제안·출처 표시. 모르면 비워두고 연료 비율 기반 비용 계산을 제한한다. 번호판/VIN은 기본 필수 아님.
- **FR-M02-1:** 차량 QR 스캔과 공동 사용자 초대는 서로 다른 요청 종류로 검증한다. 초대 수락이 차량 설치 기기의 재등록 권한을 주지 않는다.
- **FR-M02-2:** 관리자/멤버 역할과 기본 비공개 정책을 가입 전에 설명한다. 초대는 만료·취소 가능.
- **FR-M02-3:** 용량 수동 입력은 0 초과·유한수, 차량 사양과의 불일치 경고. 값이 바뀌면 이후 계산에 새 버전을 적용하고 과거 기록 변경은 별도 확인.
- **예외/완료:** 카메라 거부 시 차량 관리자의 초대 방식 안내. 만료/중복/다른 계정 초대는 명확한 오류. 한 QR를 여러 번 보내도 차량·멤버 중복 없음.

### M03. 홈

- **화면:** 선택 차량 / 확인할 기록 / 최근 운행 / 이번 달 실제 입력 지출(주유·정비) / 정비 예정. 하단 홈·운행·차계부·관리.
- **FR-M03-1:** 가장 위에 주유 확인·운행 귀속·정산 변경 등 미완료 작업을 둔다. 탭하면 M07/M04/M09/M13으로 이동한다.
- **FR-M03-2:** 본인 기록과 명시적으로 공유받은 기록만 집계. 개인/차량 공동 지출 집계 범위를 표시한다.
- **FR-M03-3:** 월 지출은 사용자 확인 거래만 합산하고 미확인 추정 건은 별도 수/금액으로 표현. 운행 소비 비용은 중복 합산하지 않는다.
- **예외/완료:** 신규 사용자는 빈 상태와 차량 등록, 오프라인은 마지막 갱신 시각. 차량을 바꾸면 이전 차량 데이터가 남아 섞이지 않는다.

### M04. 휴대폰 연결·이번 운행 사용자

- **화면:** 차량 별칭 / 연결 상태 단계 / ‘이번 운행에 내 계정 사용’ / 자동 추천 허용 / 등록 기기 관리.
- **상태:** 미등록 → 권한 필요 → 연결 중 → 앱 인증 중 → 차량 확인 대기 → 사용 중 / 만료 / 실패.
- **FR-M04-1:** Bluetooth 페어링과 fuelog 앱 인증을 별개로 보여준다. 일반 오디오 연결 성공만으로 ‘사용자 인증 완료’ 표시 금지.
- **FR-M04-2:** 서버가 발급한 짧은 수명의 차량·운행·챌린지에 묶인 증명을 전송한다. 완료 응답 전 ‘요청 보냄’으로 표시한다.
- **FR-M04-3:** 주행 중에는 ‘정차 후 적용’으로 보류하고 차량 C03과 일치시킨다. 연결 해제/배터리 절약/앱 종료 상태를 안내한다.
- **예외/완료:** BLE 미지원 시 QR/온라인 확인 방식 제공. 두 폰 동시 연결·증명 재사용·멤버 탈퇴·권한 철회에서 오인증 없음. 재연결 시 이미 끝난 운행을 가져오지 않는다.

### M05. 운행 목록

- **화면:** 차량·월 선택 / 날짜별 운행 / 거리·추정 연료비 / 비공개·공유·누락 상태.
- **진입→다음:** 운행 탭 → M06. 여행 정산은 선택한 운행의 소유/공유 권한을 확인한 후 M08.
- **FR-M05-1:** 시작·종료 시간, 거리, 기록 품질을 표시. 경로 수집 없는 MVP는 주소/지도 경로를 만들어 내지 않는다.
- **FR-M05-2:** 본인 운행과 공유받은 운행을 구분하며, 공유 범위에 없는 날짜·장소·사용자 정보를 목록에서도 숨긴다.
- **FR-M05-3:** 페이지 로딩·빈 결과·재시도를 지원. 목록 단계의 ‘공유’도 바로 실행하지 않고 공유 내용 확인 화면으로 연결한다.
- **예외/완료:** 미완료 운행에는 최종 비용 미표시. 백엔드 요청에서 타인 운행 ID를 직접 지정해도 접근 거부.

### M06. 운행 상세·공개 범위

- **화면:** 거리·추정 연료비 → 시작/종료 시각·누적거리 → 소모량·연비·적용 단가 → 데이터 품질 → ‘여행 정산에 추가’ / 공유 범위.
- **FR-M06-1:** 자동 측정 원본과 사용자가 넣은 제목·단가·메모를 구분한다. 원본 센서값을 사용자가 직접 덮어쓰지 않는다.
- **FR-M06-2:** 계산 근거를 펼치면 단위·단가 출처·탱크 용량 출처·누락/주유 여부를 확인할 수 있다. 확정 결제 비용으로 부르지 않는다.
- **FR-M06-3:** ‘비공개’ 기본값. 공유 시 그룹/사람, 거리·금액·시간 등 항목 미리보기를 제공하고 위치는 기본 제외한다.
- **FR-M06-4:** 이미 공유한 기록을 숨기면 서버 접근권한을 회수한다. 이미 전달·저장된 복사본까지 삭제되는 것은 아님을 안내한다. 정산에 포함됐으면 해당 정산 상태를 먼저 설명한다.
- **예외/완료:** 계산 불가면 수동 합의 정산 금액을 별도 입력할 수 있으나 ‘측정 운행비’로 저장하지 않는다. 단가 수정 시 관련 정산은 재확인 필요 상태가 된다.

### M07. 주유 확인·보정·수동 등록

- **화면:** ‘감지된 주유를 확인해 주세요’ / 주유소 후보·직접 입력 / 날짜·유종 / 추정량·게시 단가 / 실제 금액·주유량 입력 / ‘확인 저장’ / ‘주유 아님’.
- **진입→다음:** M03·M10·M13 또는 알림 → 저장 후 M10 상세. 수동 등록도 같은 폼을 사용하되 자동 원본 영역은 없다.
- **FR-M07-1:** 자동값을 별도 원본으로 보존하고 수정값·작성자·수정 시각·버전을 남긴다. 주유소 선택만 바꾸어도 실제 결제 금액을 자동 확정하지 않는다.
- **FR-M07-2:** 실제 금액은 정수 원, 주유량은 양수 L, 단가는 원/L. 금액만 알면 금액만 확인 거래로 저장하고 주유량은 미확인으로 남길 수 있다.
- **FR-M07-3:** 금액·양·단가가 모두 입력되어 불일치하면 할인/반올림 여부를 안내하고 사용자가 입력한 실제 금액을 보존한다. 시스템이 맞추려고 몰래 한 필드를 바꾸지 않는다.
- **FR-M07-4:** F01의 차량 감지 위치로 검색한 오피넷 후보는 거리·유종·가격 기준 시각과 함께 표시한다. 후보 위치의 측정 시각도 보여 주고, 모바일 현재 위치와 혼동하지 않는다. ‘찾는 주유소가 없어요’ 직접 입력을 제공한다.
- **FR-M07-5:** ‘주유 아님’은 후보를 기각하며 같은 샘플 구간에서 다시 알림을 만들지 않는다. 휴지통/수정 이력으로 잘못된 기각을 복구할 수 있게 설계한다.
- **예외/완료:** 동시 수정은 버전 충돌 안내, 오프라인은 임시 저장. 20L·1,700원/L 후보를 실제 33,000원으로 고치면 원본 34,000원과 확인값 33,000원이 구분되며 재전송 중복 없음.

### M08. 여행 정산 만들기

- **화면:** 여행명 / 포함 운행 선택 / 정산 기준 금액 / 참여자 / 균등 분할 또는 직접 금액 / 공유 미리보기 / ‘정산 공유’.
- **FR-M08-1:** 기본 기준은 선택 운행의 추정 연료비 합계. 사용자 합의 금액으로 변경 가능하며 ‘직접 입력’ 출처를 남긴다. 주유 구매 전액을 운행비와 동시에 더하지 않는다.
- **FR-M08-2:** 참여자는 차량 전체 멤버 자동 선택이 아니라 직접 지정. 운행 상세 공유 없이 합계·분담액만 공유할 수 있다.
- **FR-M08-3:** 원 단위 분담액 합이 총액과 일치해야 한다. 균등 분할 잔여 원은 미리보기에서 지정된 순서대로 배분하며 누가 추가 1원을 내는지 표시한다.
- **FR-M08-4:** 운행 중복 포함·다른 정산에 이미 사용된 운행을 경고한다. 중복 청구 방지를 기본으로 하고 별도 합의 시 사유를 남긴다.
- **예외/완료:** 10,000원/3명은 3,334·3,333·3,333원. 누락 운행은 자동 합계에서 제외 사유 표시. 공유 버튼 전에는 상대방에게 알림이나 데이터 전송 없음.

### M09. 정산 상세·공유받은 정산

- **화면:** 여행명 / 총액·금액 출처 / 내 분담액 / 참여자 분담액(허용 범위) / 상태 / 변경 내역.
- **FR-M09-1:** 작성자는 수정·취소, 참여자는 자신에게 공유된 범위만 확인한다. 실제 결제/송금 기능은 이번 범위 밖이다.
- **FR-M09-2:** ‘받음/완료’ 표시는 사용자가 기록한 수기 정산 상태임을 명시한다. 은행 검증 완료처럼 표현하지 않는다.
- **FR-M09-3:** 공유 후 총액·분담액 변경 시 새 버전과 재확인 상태를 만들고 대상자에게 한 번 알린다. 기존 확인 이력 보존.
- **예외/완료:** 탈퇴/공유 취소 후 신규 접근 차단. 다른 참여자의 비공개 운행 상세로 이동 불가. 취소된 정산 링크는 취소 상태만 표시.

### M10. 차계부 — 주유·정비 내역

- **화면:** 월·차량 / 사용자 확인 지출 합계 / 주유·정비 필터 / 날짜순 거래 / ‘주유 추가’·‘정비 추가’.
- **FR-M10-1:** 주유는 M07, 정비는 M11로 이동. 미확인 후보는 확인 지출 합계에서 제외한다.
- **FR-M10-2:** 개인 거래와 차량 공동 관리 거래를 분리 표시한다. 정비 항목 공유와 개인 결제 금액 공개는 별도 설정이다.
- **FR-M10-3:** 월간 합계와 항목별 합계가 같은 필터·동일한 확인 상태를 기준으로 계산되어야 한다.
- **예외/완료:** 삭제/기각/복구가 합계에 반영되고, 운행 연료비는 지출 합계에 재합산되지 않는다. 초기 빈 화면에서 수동 등록 가능.

### M11. 정비 등록·상세

- **화면:** 날짜 / 정비소 / 당시 누적거리 / 정비 항목 여러 개 / 항목별 비용 또는 총액 / 다음 정비 주기 / 공개 범위.
- **입력:** 날짜·정비 항목 필수. 누적거리·금액을 모르면 미입력으로 저장 가능하되 각각 거리 기반 추천·지출 합산 제외. 금액 0원은 무상 정비로 명시 가능.
- **FR-M11-1:** 자동 제안 누적거리는 해당 시점에 가장 가까운 유효 샘플과 측정 시각을 함께 표시. 방문일이 과거면 현재 누적거리를 조용히 대입하지 않는다.
- **FR-M11-2:** 엔진오일·타이어·필터 등 항목과 부품/공임/총액을 기록한다. 총액만 입력한 경우 항목별 비용을 임의 배분하지 않는다.
- **FR-M11-3:** 정비소 방문 추정은 선택적 등록 제안이다. 교체 부품·가격은 사용자가 확인한다. 주유소 경정비 시설 플래그는 전체 정비소 데이터베이스가 아니다.
- **FR-M11-4:** 정비 이력을 차량 멤버와 공유할지, 비용·메모까지 공유할지 각각 선택한다. 영수증 첨부는 후속 기능으로 둔다.
- **예외/완료:** 과거/다음 기록과 누적거리 순서가 맞지 않으면 확인 요청. 42,000km에서 엔진오일 기록, 주기 10,000km를 설정하면 52,000km 예정 생성(예시일 뿐 제조사 권장값 아님).

### M12. 정비 예정·추천 근거

- **화면:** 예정 항목 / 마지막 정비일·거리 / 다음 거리·날짜 / 주기 출처 / ‘정비 기록하기’ / 알림 설정.
- **FR-M12-1:** 주기는 해당 차량 제조사 관리 기준이 확보되면 그 근거를 연결하고, 아니면 사용자 지정값으로 명시한다. 모든 차에 같은 주기를 공식 권장값처럼 적용하지 않는다.
- **FR-M12-2:** 마지막 정비 기준 거리+설정 주기, 날짜+기간을 계산하고 먼저 도래한 조건을 표시. 원시 센서로 부품 고장을 진단하는 기능은 아니다.
- **FR-M12-3:** 알림은 도래/초과 상태 변화에 따라 중복 억제. 최신 누적거리가 오래됐으면 남은 거리 옆에 갱신일 표시.
- **예외/완료:** 기준 이력·주기가 없으면 입력 요청. 정비 기록을 수정/삭제할 때 추천 근거와 다음 일정이 일관되게 재계산된다.

### M13. 알림함·확인할 기록

- **화면:** 주유 확인 / 운행 사용자 확인 / 정산 공유·변경 / 정비 예정 / 동기화 문제. 읽음과 처리 완료를 구분한다.
- **FR-M13-1:** 서버에 확인 작업을 먼저 저장하고 푸시는 접근을 돕는 수단으로 사용한다. 같은 이벤트·수신자·버전에 알림 한 건.
- **FR-M13-2:** 잠금 화면 문구는 ‘확인할 차량 기록이 있어요’. 주유소·금액·이동 시간·실명 등 민감 내용을 기본 푸시에 넣지 않는다.
- **FR-M13-3:** 딥링크는 로그인과 현재 멤버십/소유권 재검사 후 M07/M06/M09/M12로 이동한다. ID만 알면 열리는 링크 금지.
- **예외/완료:** 알림 권한 거부·토큰 만료·푸시 실패여도 앱 내 작업 확인 가능. 이미 해결/삭제/공유 취소된 기록은 해당 상태로 표시.

### M14. 차량·멤버·기기·공유·계정 관리

- **화면:** 차량 설정 / 멤버 / 등록 휴대폰 / 기본 공개 범위 / 권한·알림 / 계정·데이터. 항목 선택 시 하위 화면으로 이동해 한 화면에 긴 설정 폼을 쌓지 않는다.
- **FR-M14-1:** 관리자만 차량 기본 정보·초대·멤버 해제를 관리한다. 관리자 역할이 개인 운행 열람 권한으로 확대되지 않는다.
- **FR-M14-2:** 공유는 기본 비공개. 일괄 공개 범위 변경 시 적용할 기록·필드를 미리 보여주고 확인한다. 새 설정으로 과거 기록까지 자동 공개하지 않는다.
- **FR-M14-3:** 분실 폰 연결 증명과 세션을 폐기하고 이후 인증을 거부한다. 차량 판매/등록 해제는 차량 기기 연결·멤버십·개인 기록 보관을 각각 처리한다.
- **FR-M14-4:** 위치/근처 기기/알림 권한 철회 안내, 로그아웃, 계정 삭제 요청, 데이터 삭제/보관 범위 설명을 제공한다. 공동 정산에 이미 공유한 항목의 처리도 명시한다.
- **예외/완료:** 마지막 관리자는 역할 양도 또는 차량 폐쇄 확인 없이 탈퇴하지 못한다. 멤버 제거·공유 회수는 모든 API와 로컬 캐시에 반영된다.

## 6. 기능 처리 흐름과 데이터 계약

### 6.1 운행 기록

1. 앱/기록 서비스 실행 가능 상태 확인 → 차량 서비스 연결 → 지원·권한·현재 가용성 검사.
2. 최초 유효 누적거리·연료·단위·센서 시각·수신 시각 저장. 사용자 확정 전에는 제한된 임시 세션.
3. 필요한 이벤트 구독과 제한된 체크포인트로 암호화 저장. 연속 고빈도 폴링을 전제로 하지 않음.
4. 지원되는 운행 종료 신호 또는 명시적 종료 시 최종 샘플 저장. 종료 콜백을 놓치면 다음 시작에 복구하고 누락 표시.
5. 로컬 outbox → HTTPS 서버 전송 → 서버 검증·중복 제거 → 모바일 운행 목록 반영.

**시동 OFF·부팅·절전 복귀는 앱 생명주기와 동일하지 않다.** 자동 시작·전원 이벤트 수신·백그라운드 지속 실행은 대상 플랫폼에서 검증해야 한다. 현재 진단 Activity는 `onStop()`에서 측정을 정리하는 구조이므로 그 코드만으로 화면 밖 자동 기록이 구현됐다고 볼 수 없다. 기존 부팅 검토 보고서의 미확인 조건도 유지한다.

### 6.2 주유 후보

`기준 샘플 있음 → 증가 감지 → 안정성 재확인 → 후보 저장 → 위치/단가 보강(F01) → 모바일 확인 대기 → 사용자 확인 또는 기각`

안정성 초기 실험값 제안: 동일 증가 상태가 30–60초 범위의 유효 샘플 3개 이상에서 유지되는지 확인. 이는 센서 검증 전 가설이며 공식 요구가 아니다. 지원되는 샘플 빈도에 따라 조정하고, 오래된 샘플을 세 번 읽은 것을 세 번 측정한 것으로 세지 않는다. 자동 알림은 후보가 서버에 저장된 뒤 생성한다. 네트워크가 없으면 후보 먼저 보관하고 위치·가격 보강을 나중에 수행한다.

### 6.3 서버 책임과 저장 객체

Android Studio는 개발 도구이며 앱 자체를 공용 DB 서버로 삼지 않는다. **Supabase Auth + Postgres/RLS + Edge Functions 등 서버 실행 계층**을 둔다. 별도의 상시 VM은 필수는 아니다. 모바일의 사용자 범위 CRUD는 인증된 API와 RLS로 가능하지만, 차량 수집·운행 귀속·Opinet 키 사용·공유·알림 발송은 서버에서 검증한다. DB 관리자 자격증명과 `service_role` 키를 앱에 넣지 않는다.

| 객체 | 필수 데이터 | 권한/불변 조건 |
| --- | --- | --- |
| vehicle / membership | 앱 차량 ID, 별칭, 유종, 용량·출처·버전, 멤버·역할 | 멤버십으로 개인 기록 전체 조회 불가 |

### 6.4 신규 기능 F01. Pleos 차량의 주유 감지 위치로 주유소 게시가격 조회 (2026-11-06)

**담당과 연결:** 위치 입력은 Pleos 차량 앱 C05의 주유 후보에서 생성한다. 서버는 좌표 변환과 오피넷 조회를 수행한다. C05는 결과를 읽기 전용 후보로 보여 주고, 모바일 M07에서 사용자가 실제 주유소·주유량·결제 금액을 확인한다. 모바일의 현재 GPS를 차량에서 감지한 주유의 위치로 조용히 대입하지 않는다. 독립된 차량 화면을 추가하지 않는다.

**흐름:** `연료 증가 최초 관측 → 후보 ID 고정 → 차량 위치 1회 요청 → 연료 증가 안정성 확인 → 후보와 위치 증거를 서버에 전송 → 주변 주유소 검색 → 유종별 게시가격·기준 시각 조회 → C05 후보 표시 → M07 사용자 확인`.

- **FR-F01-1 · 위치 취득:** 사용자가 차량 위치 보조에 동의하고 `pleos.car.permission.FUSED_LOCATION`이 이미 허용된 경우에만, 증가를 최초 관측한 시점에 Pleos FusedLocation의 새 위치 업데이트 1건을 요청한다. `PleosLocationClient.getCurrentLocation()`은 SDK 업데이트 콜백을 한 번 수신하는 앱 래퍼이며 새 GNSS 측정을 보장하는 API가 아니다. 10초 내 응답이 없으면 위치 없이 후보를 남긴다. 주행 중 권한 팝업이나 장소 선택 화면을 띄우지 않는다. 권한 안내·설정은 정차 중 C07에서 제공한다. [L1][L2]
- **FR-F01-2 · 감지 위치 연결:** 좌표와 `measuredAt`, 수신 시각, `source=PLEOS_CURRENT_UPDATE`, 위치 요청을 시작한 `candidateId`를 함께 묶는다. 위도·경도의 유한 범위와 시각을 검사하고, 측정 시각이 해당 감지 구간과 겹치지 않거나 감지 뒤 이동한 위치임이 확인되면 자동 검색 입력으로 쓰지 않는다. 마지막 저장 위치(`getLastKnownLocation`)를 현재 위치라고 표시하거나 다른 후보 ID에 재사용하지 않는다. SDK의 `confidence`를 근거 없이 미터 정확도로 환산하지 않는다.
- **FR-F01-3 · 후보 확정 전 제약:** 연료 증가가 안정성 검사를 통과하고 현재 운행 사용자가 서버에서 검증된 경우에만 검색을 시작한다. 연료 미지원, 사용자 미확정, 위치 거부·차단·`null`·시간 초과, 차량 앱 미실행 중 감지, 후보 취소에서는 위치 조회를 건너뛰거나 결과를 폐기한다. 연료 후보 자체는 보존하고 C05에 ‘주유소 미확인’을 표시한다.
- **FR-F01-4 · 서버 검색:** 차량 앱은 좌표·측정 시각·후보 ID를 인증된 HTTPS **본문**으로 보낸다. 서버는 설치와 후보 소유권·유종·좌표 범위·시간 신선도를 다시 검사한다. Pleos `LocationData`의 좌표계는 현재 열람한 공개 설명에서 확정되지 않았으므로 대상 SDK/기기에서 좌표계 확인을 선행하고, 검증된 변환으로 오피넷 요청용 **KATEC X/Y**를 만든다. 좌표계를 확인하지 못하면 검색하지 않는다. 오피넷 `aroundAll.do`는 유종 코드와 반경을 요구한다. 초기 검색 반경은 1 km, 결과가 없으면 3 km로 한 번 넓히며 공식 최대 5 km를 넘기지 않는다. 거리순 상위 3곳만 후보로 둔다. 이 반경·개수는 제품 초기값이다. [O1]
- **FR-F01-5 · 가격 근거:** 주변 검색의 `PRICE`만으로 게시 시각을 추정하지 않는다. 각 주유소 ID에 대해 서버가 `detailById.do`의 같은 유종 `PRICE`, `TRADE_DT`, `TRADE_TM`을 조회해 주유소 ID·상호·거리·게시 단가(원/L)·가격 기준 시각·조회 시각을 저장한다. 유종 불명, 가격 누락/0, 시각 파싱 실패 또는 기준 시각이 조회 시점보다 24시간 이상 오래된 경우에는 유효한 추정 단가로 쓰지 않는다. 24시간은 제품 초기값이며 오피넷의 갱신 주기·운영 조건에 따라 조정한다. [O2][O3]
- **FR-F01-6 · 화면과 계산:** C05에는 ‘인근 주유소 후보’, 유종, 거리, **게시 단가와 기준 시각**을 표시한다. 여러 곳이면 특정 상호·가격을 실제 주유처/결제 단가로 자동 확정하지 않는다. 하나만 있어도 후보로 표시한다. 추정 금액은 사용자가 M07에서 후보 주유소를 선택하고 유효한 탱크 용량·추정 L·가격 근거가 갖춰진 경우에만 `추정 L × 게시 원/L`로 계산한다. 선택 전에는 후보별 가격만 보여 주며 단일 추정 금액을 만들지 않는다. 할인·포인트·실결제 금액은 모바일 입력으로만 확정한다.
- **FR-F01-7 · 저장·보호:** 오피넷 인증키와 좌표 변환/조회 코드는 서버에 둔다. 원시 좌표는 후보 보강 작업에만 사용하고 정상 완료 또는 실패 후 24시간 이내 삭제하는 초기 보존안을 적용한다. 후보에는 검색 결과 ID·가격 근거만 남기며 일반 그룹 조회와 로그에 원시 좌표를 내보내지 않는다. 사용자 동의 철회나 후보 삭제 시 남은 좌표도 삭제한다. 이 보존안은 출시 전 개인정보 처리 문서와 맞춘다.
- **FR-F01-8 · 재시도·갱신:** 동일 `candidateId`와 위치 증거의 재전송은 같은 검색 작업 한 건으로 처리한다. 오피넷 실패/429/시간 초과는 유한 재시도와 서버 캐시를 사용하되 오래된 가격을 ‘현재가’로 승격하지 않는다. 늦게 도착한 결과는 후보의 최신 revision, 사용자 귀속, `CONFIRMED/REJECTED` 상태를 확인한 뒤 적용한다. 주행 제한 진입 중 결과 팝업이나 자동 화면 전환은 하지 않고 다음 정차 조회에서 확인한다.

**서버 계약 제안:** 기존 `POST /fuel-candidates/{id}/station-search`에 `candidateId`, `latitude`, `longitude`, `measuredAt`, `source`, `fuelType`, `locationOperationId`를 받는다. 서버는 body의 사용자 ID·차량 ID를 권한 근거로 신뢰하지 않는다. 응답은 `candidateId`, `revision`, `searchStatus`, `locationMeasuredAt`, `stations[] {stationId, name, distanceMeters, fuelType, postedPriceWonPerLiter, pricePostedAt, priceFetchedAt, priceStatus}`로 제한한다. 가격 상태는 `VALID/STALE/UNAVAILABLE`로 구분한다. 앱에 오피넷 키나 KATEC 좌표를 돌려줄 필요는 없다.

**완료 기준:** 차량 위치 한 건이 해당 주유 후보에만 연결되고, 좌표계를 검증하지 않은 위경도를 오피넷 X/Y에 그대로 넣지 않는다. 위치/유종/가격 시각이 부적합하면 원본 주유 후보는 남지만 게시가격과 추정 금액은 숨긴다. 동일 후보 재전송은 검색·모바일 확인함 각 한 건이다. 후보가 1곳이거나 여러 곳이어도 모바일 확인 전 실제 주유소·금액으로 확정되지 않는다. 위치 권한 거부, SDK `null`/오류, 이동 뒤 늦은 위치, 오피넷 장애, 주행 제한 진입을 각각 검증한다.

오피넷 호출은 서버 캐시·중복 억제를 적용하고 발급 키의 현재 호출량·이용 조건을 확인한다. 네트워크 실패 시 과거 게시 가격을 ‘현재 실결제 단가’로 사용하지 않는다. 정비소 검색은 별도 장소 데이터 제공자/수동 입력 범위이며 오피넷만으로 완성되는 기능이 아니다.

현재 로컬 기준은 Vehicle 2.3.2 / FusedLocation 1.1.3이다. `docs/vehicle-diagnostics.md`에 기록된 과거 에뮬레이터 실행에서는 Pleos 연료 API가 미지원 응답, AAOS 연료/누적거리 config가 현재 권한에서 노출되지 않았다. **메서드 존재만으로 자동 주유·연비 기능 구현 가능을 확정할 수 없다.** 이번 작업에서 실차·에뮬레이터 API를 다시 실행하지 않았다.
